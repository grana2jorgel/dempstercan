Poner DempsterCan en el móvil

Del archivo dempstercan.zip a un icono en la pantalla de inicio del teléfono, funcionando sin conexión. Todos los pasos, sin dar por sabido nada.

Tiempo total unos 20 minutos Hace falta una cuenta de GitHub, gratuita No hace falta saber programar

Marque los pasos según los complete. El navegador recuerda por dónde iba, así que puede cerrar esta página, ir al teléfono y volver.

01

Preparar la carpeta en el ordenador

3 min

El objetivo de esta parte es tener en el escritorio una carpeta con todos los archivos, incluidos los que el sistema esconde por empezar por punto.

  1. Descargue dempstercan.zip de la conversación y descomprímalo. En Windows: clic derecho → Extraer todo. En Mac: doble clic.

  2. Abra la carpeta dempstercan que ha aparecido. Dentro debe ver index.html, y las carpetas js, css, icons, docs, test y tools.

  3. Active la vista de archivos ocultos. Este paso no es opcional: hay una carpeta llamada .github que el sistema esconde y que contiene las instrucciones que hacen que GitHub publique la app sola.

    WindowsExplorador → pestaña Vista → marcar Elementos ocultos
    MacEn el Finder, pulse ⌘ ⇧ .
✓
Debe ver ahora .github y .gitignore en la carpeta. Si no aparecen, vuelva al paso 3: sin ellos la publicación automática no funcionará.
02

Crear el repositorio en GitHub

8 min

Aquí hay dos caminos. Llevan al mismo sitio; elija uno según lo que ya tenga instalado.

Camino A · recomendado

Por el navegador

Arrastrando los archivos a la web de GitHub.

  • No instala nada
  • Todo con el ratón
  • Para actualizar hay que volver a subir
Camino B

Con Git

Cuatro comandos en una terminal.

  • Requiere instalar Git
  • Actualizar después es un solo comando
  • Guarda el historial de cambios

Antes de elegir: crear la cuenta y el repositorio vacío

  1. Si aún no tiene cuenta, créela en github.com/signup. Es gratuita y basta un correo.

  2. Vaya a github.com/new y rellene:

    Repository namedempstercan
    VisibilidadPublic — hace falta para publicar la web sin pagar. La app no contiene datos de pacientes.
    Add a READMEDesmarcado
    Add .gitignore / licenseNone en los dos

    Pulse Create repository.

Si marca alguna de esas tres casillas, GitHub crea archivos que chocarán con los suyos y el paso siguiente dará error. Si ya le ha pasado, borre el repositorio en Settings → Danger Zone → Delete this repository y vuelva a crearlo vacío.

Camino A — subir por el navegador

  1. En la página del repositorio recién creado, pulse el enlace uploading an existing file.

  2. Abra la carpeta dempstercan en el explorador, seleccione todo su contenido con Ctrl A (o ⌘ A) y arrástrelo a la ventana del navegador.

    Arrastre el contenido, no la carpeta que lo envuelve. Espere a que la lista termine de cargar: son unos cincuenta archivos.

  3. Abajo, en el cuadro de mensaje, escriba primera version y pulse Commit changes.

  4. Compruebe en la lista de archivos que aparece la carpeta .github. Si no está, es que el arrastre no incluyó los archivos ocultos: pulse Add file → Create new file, escriba como nombre .github/workflows/pages.yml, pegue dentro el contenido de ese archivo de su carpeta, y guarde. Repita con .github/workflows/apk.yml.

Camino B — con Git

  1. Instale Git si no lo tiene, desde git-scm.com/downloads. Después abra una terminal (en Windows, Git Bash; en Mac, Terminal) y sitúese en la carpeta:

    cd /ruta/hasta/dempstercan

    Truco: escriba cd y un espacio, y arrastre la carpeta a la terminal; la ruta se escribe sola.

  2. Cree el repositorio local y el primer commit. Cópielo entero de una vez:

    git init
git add -A
git commit -m "DempsterCan 1.1"
git branch -M main

    Si es la primera vez que usa Git, le pedirá su nombre y correo; siga las instrucciones que él mismo imprime.

  3. Conecte con GitHub y suba. Cambie USUARIO por su nombre de usuario:

    git remote add origin https://github.com/USUARIO/dempstercan.git
git push -u origin main

  4. Cuando pida credenciales, la contraseña de GitHub no vale. Hay que usar un token: github.com/settings/tokens → Generate new token (classic) → marque el permiso repo → copie el token y péguelo donde pide la contraseña.

    Alternativa más cómoda si la prefiere: instalar GitHub CLI y ejecutar gh auth login una sola vez.

✓
Recargue la página del repositorio: debe ver la lista de archivos con index.html y README.md renderizado debajo.
03

Publicar la app

4 min

GitHub va a servir la app como una página web con dirección propia. Es lo que después se instala en el teléfono.

  1. En el repositorio: pestaña Settings → en la columna izquierda, Pages.

  2. En Build and deployment → Source, despliegue y elija GitHub Actions. No hay que guardar nada: el cambio se aplica solo.

  3. Vaya a Settings → Actions → General, baje hasta Workflow permissions y marque Read and write permissions. Pulse Save.

  4. Abra la pestaña Actions. Verá una ejecución llamada Publicar en GitHub Pages. Tarda entre uno y tres minutos; primero pasa las 37 pruebas del motor de cálculo y solo publica si están todas en verde.

  5. Cuando termine, vuelva a Settings → Pages: arriba aparece la dirección.

    https://USUARIO.github.io/dempstercan/

    Ábrala en el ordenador para confirmar que carga. Debe ver la pantalla de la app con el lienzo en blanco.

Si la ejecución falla, entre en ella y mire el paso marcado en rojo. Los dos motivos habituales son que Source siguiera en Deploy from a branch (paso 2) o que faltaran los permisos de escritura (paso 3).

04

Instalarla en el teléfono

3 min

A partir de aquí, todo ocurre en el móvil.

  1. Abra Chrome en el teléfono y escriba la dirección del paso anterior. Lo más cómodo es enviársela por correo o WhatsApp desde el ordenador.

  2. Menú de tres puntos arriba a la derecha → Añadir a pantalla de inicio. En algunas versiones de Chrome aparece como Instalar aplicación.

  3. Confirme el nombre. Queda un icono en el escritorio igual que cualquier otra app, y al abrirla desde ahí no se ve la barra del navegador.

  4. Ábrala una vez con datos o wifi y deje que cargue del todo. En esa primera apertura se guardan todos los archivos en el teléfono.

  5. Pulse Tomar foto con la cámara. Chrome pedirá permiso: acéptelo. Si lo rechazó sin querer, se recupera en Chrome → tres puntos → Configuración → Configuración de sitios → Cámara.

  6. Active el modo avión y abra la app otra vez. Debe funcionar igual. Esa es la comprobación de que ya no depende de la red.

Por qué la dirección tiene que ser la de GitHub y no la de su ordenador. Los navegadores solo dan acceso a la cámara en páginas servidas por HTTPS. Si abre la app desde la IP local del ordenador —algo como http://192.168.1.40:8080— funcionará todo menos la cámara. La dirección de GitHub Pages es HTTPS y no tiene ese problema.

05

El APK, si lo prefiere

10 min · opcional

Un archivo instalable de Android, útil si el repositorio tiene que ser privado o si quiere repartir la app a compañeros sin darles una dirección web. Con la parte 4 hecha, esto no hace falta.

  1. Publique una etiqueta de versión. Con Git:

    git tag v1.1.0
git push origin v1.1.0

    Por el navegador: en el repositorio, Releases → Create a new release → Choose a tag, escriba v1.1.0, y publique.

  2. Pestaña Actions → ejecución APK de Android. La primera vez tarda entre cinco y diez minutos porque descarga el SDK de Android.

  3. Descargue el archivo .apk desde Releases, y pásela al teléfono por correo, cable o Drive.

  4. Ábrala desde la app Archivos del teléfono. Android avisará de que viene de un origen desconocido: pulse Configuración en ese mismo aviso, active el permiso, vuelva atrás y pulse Instalar.

Aviso honesto. La compilación del APK no se pudo ejecutar en el entorno donde se escribió la app, porque no tenía acceso al registro de paquetes de npm. La configuración está completa y es la estándar, pero la primera ejecución en GitHub es donde se valida de verdad. Si falla, el registro de la ejecución señala la causa con claridad y suele ser una versión que hay que fijar. La parte 4 no depende de esto.

El APK va firmado con la clave de depuración: sirve para instalarlo a mano, pero no para subirlo a Google Play.

06

Actualizar la app más adelante

1 min

Si cambia algo del proyecto, con Git basta con:

git add -A
git commit -m "lo que haya cambiado"
git push

Por el navegador: Add file → Upload files y vuelva a subir los archivos modificados.

GitHub republica sola. En el teléfono, la versión nueva entra la segunda vez que abra la app: la primera se descarga en segundo plano. Si quiere forzarlo, ciérrela del todo y ábrala dos veces seguidas.

07

Si algo no sale

Lo que veQué pasa y cómo se arregla
Pantalla en blanco al abrir index.html con doble clic La app está hecha de módulos que el navegador bloquea al abrirlos como archivo suelto. No es un fallo: hay que servirla por web, que es justo lo que hace GitHub Pages.
Pages dice 404 La publicación aún no ha terminado, o Source no está en GitHub Actions. Revise la pestaña Actions.
No aparece Añadir a pantalla de inicio Tiene que ser Chrome o Edge sobre la dirección HTTPS de GitHub. En Firefox de Android la opción se llama Instalar.
El botón de la cámara no hace nada Falta el permiso, o la página no está en HTTPS. La app pasa sola al selector de galería, así que siempre puede seguir trabajando con fotos ya hechas.
Actions falla con error de permisos Settings → Actions → General → Workflow permissions → Read and write permissions.
Pages no está disponible El repositorio es privado, y eso requiere cuenta de pago. Hágalo público en Settings → General → Change visibility, o use el APK.
git push rechaza las credenciales GitHub no acepta la contraseña de la cuenta desde la terminal. Hace falta un token de acceso personal (parte 2, camino B, paso 6).

  • Una regla rígida o cinta métrica que pueda dejar apoyada en el mismo plano que el perro. Sin ella no hay centímetros, ni newtons, ni momentos articulares: solo ángulos y porcentajes.
  • La masa corporal del paciente, de la báscula.
  • Si dispone de ellas, dos o cuatro básculas para el reparto de carga medido. Con dos ya se cubre el reparto torácico frente a pelviano, que es el dato principal.
  • Una cinta métrica flexible para los perímetros torácico y abdominal, que son los que más afinan el reparto de masa en perros obesos, braquicéfalos o con atrofia muscular.
